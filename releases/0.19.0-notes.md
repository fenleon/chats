Chats 0.19.0 — the instant-thread build — R8 APK (16.7 MB)

## Features

- The thread store: rooms open instantly. Every message is materialized into a local store the moment it syncs, so opening a room is a paged read instead of recomputing the page from the raw timeline — re-opening a room no longer rebuilds anything, and cold opens paint a first page fast while the rest fills in behind it.
- Local history: scrolling up reads from the store; when deeper history is needed, one bounded catch-up round fetches it, so walking back through a room is continuous instead of stopping at what the sync had cached.
- Fresh logins backfill recent history per room automatically (bounded, resumable, capped) so a new install doesn't start from an empty thread.
- Markdown: send and render **bold**, *italic*, lists and headings.
- Replies: reply to any message from its context window; replies carry an excerpt header on the row.
- Copy & paste: copy a message's text from its context window; paste into the composer.
- One-line account status: the account screen shows "Syncing messages… x of y" while the fresh-login backfill runs, then "Synced · up to date" — honest progress without a permanent counter.
- Opt-in diagnostics log: a Settings toggle writes a privacy-safe status/timing log (no message bodies, names, or URLs with tokens) that you can export and share when reporting an issue. Off by default.

## Bug fixes

- Messages you sent could go missing from a room's view — when a just-sent message's decryption lost a race at sync time, the store skipped it permanently and nothing retried. The ingest now re-reads and heals it, and every app start repairs any recent messages that were skipped by earlier versions.
- Old messages could show as permanently "[Encrypted message]" after a fresh login — history that failed to decrypt before the keys arrived was never retried, and nothing projected it into the store. A convergent background repair now projects every room's full history and re-decrypts whatever the on-device keys can unlock (571 messages healed on the live account; only truly keyless history stays as an honest placeholder).
- After a fresh login the room list could hide most rooms (293 of 362 on the live account) — the fresh-login projection wrote placeholder rows that the bridge's history-import rule treated as "already has a head", so rooms never got a real timestamp and the list guard hid them. Fixed: placeholder rows no longer block imports, and a reconcile pass republishes any room the updater missed.
- The room list could flap to "Can't reach server" on WiFi↔mobile handoffs while messages kept flowing — a single dropped sync round now has to persist 15 s before the banner shows; real outages still appear (15 s later).
- Messages to yourself (Note to self) could stick on "sending" and then flip back from "sent" — the send-confirmation bookkeeping only ran in a code path that no longer executes. Retirement now happens where the message actually lands.
- Scrolling up in a long room could dead-end with "earlier messages" never appearing. Fixed (link repair + bounded catch-up), and the underlying row-builder divergence that caused it is removed.
- Room open could freeze the app for tens of seconds on large accounts (cold-open and media work ran on the UI thread). Both moved off it.
- Hardware keys and haptics died after an LP3 firmware update — the background relay bound once and never rebound when the system service restarted. It now rebinds on demand, so wheel/camera/brightness/haptics survive firmware updates and reboots.
- Contact resolution for bridge chats (WhatsApp/Instagram) no longer fires an unbounded burst of lookups per room open (deduped and capped).
- Room-list badges/junk rows: bursty bridge re-imports and receipt traffic no longer bump rooms to the top with phantom unread counts (ingest-time projection with a two-decision head/unread model).
- Reply and forward fixes: replies resolve their header immediately instead of waiting for the sync echo; forwarded-message headers strip cleanly; markdown list items interrupt paragraphs correctly.

## Known / outstanding

- A room opened while history is still restoring can show stale "[Encrypted message]" blocks until the app is restarted — the stored data is correct; the in-memory page view needs a restart to pick up the heal. Fix queued (render-path rework).
- A room opened for the very first time can stay on the short first page until you re-open it (a refresh notification can be missed; data is fine, re-opening shows everything). Fix queued.
- A handful of genuinely unrecoverable messages (keys never backed up, or server-pruned content) stay as "[Encrypted message]" placeholders — honest, not fixable on-device.
- History older than the backfill window arrives as you scroll rather than upfront; a one-time bulk backfill on upgrade is a decision still open.
- Delivery speed once the message leaves the phone is Beeper's relay latency — unchanged by this release.

Chats 0.19.1 — the caught-up build — R8 APK (16.7 MB)

## Features

- Renamed to **Messages** — the toolbox entry, notifications and account screen now say Messages. Display only: your account, data and settings are untouched.
- The message store is finished: every page — live messages, history scroll-up, repairs, seeded pages — now flows through a single owner, so the store can no longer drift from what the thread shows. What that fixes in practice: background repair no longer freezes on rooms whose decryption keys arrived late (rooms that had been stuck since 0.19.0 now heal on first start), scrolling into old history no longer dead-ends or repeats, and rooms marked done too early are re-visited until their history actually renders.
- None besides — the rest of this release is fixes.

## Bug fixes

- Google Messages (RCS) photos could arrive as a bare filename like `IMG_0897.heic` instead of a picture. The bridge delivers photos as a "Waiting for attachment…" notice that is later edited into the real image, and the new message store folded that edit as a text change without re-classifying it — the row kept its system-line style wearing the file name. Edits to media now re-classify the row, so notice→photo transitions render as pictures (live, no reload), and a one-time repair at first start re-classifies rows the previous version got wrong.
- "Save diagnostics file" always failed with "Save failed" — the export asked Android's media store for a text file in the video collection, which rejects non-video types outright. The save now goes through the accepted path; the file still lands in Movies/Chats (reachable over MTP) as `chats-diagnostics-<date>.log.mp4`.
- Rooms could stay marked unread and their notifications never dismissed — re-opening a thread skipped the read receipt (a scroll-restore optimization turned into a permanent skip once the background poll stopped re-marking), so the badge, the "seen" tick for the sender, and the notification cancel all never ran. Opening a thread now always marks it read up to what you've seen, and a stale cached sync filter that drops read-receipt echoes is refreshed (one re-upload on first start), so the badge stays clear after the sync round confirms it.

## Known / outstanding

- Re-opening a room very quickly after it was first opened can briefly show the cached page while the fresh one loads; a rare fetch can come back empty until the next tap — the underlying data is correct.
- A room that is genuinely behind its newest message when read (e.g. messages arriving mid-open) stays honestly unread; a notification for such a room can re-appear once per app start until it is read.
- A handful of genuinely unrecoverable messages (keys never backed up, or server-pruned content) stay as "[Encrypted message]" placeholders — honest, not fixable on-device.
- Delivery speed once the message leaves the phone is Beeper's relay latency — unchanged by this release.
